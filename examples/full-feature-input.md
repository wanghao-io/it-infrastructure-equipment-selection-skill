# Full-Feature Project Input Example

这个示例用于一次性触发 `it-infrastructure-equipment-selection` Skill 的主要能力：

- 场景模板与 guided requirement discovery；
- 架构决策；
- Server / Storage / Historian / Network / UPS sizing；
- SCADA / industrial IT/OT 规划；
- Mandatory constraint gate + preference ranking；
- 当前设备选型与实时价格研究；
- 已有预算 revision guard；
- 3/5 年 TCO；
- 厂商/型号比较；
- 招标/RFQ 参数；
- Mermaid / Graphviz 网络拓扑；
- 合规与风险检查；
- BOM 与项目预算。

> Codex 可使用 `$it-infrastructure-equipment-selection`。Claude Code 可将第一行替换为 `/it-infrastructure-equipment-selection`。其他 Agent Skills 兼容 Host 按各自调用方式使用。

```text
$it-infrastructure-equipment-selection

你是一名负责制造业 IT/OT 基础设施方案、设备选型和采购技术支持的高级解决方案工程师。

请为一个中小型制造工厂的一期集中监控与 IT/OT 基础设施项目做完整方案，并同时执行本 Skill 支持的 guided requirements、架构决策、容量规划、Mandatory 约束过滤、推荐排序、TCO、实时价格研究、厂商比较、招标参数、网络拓扑、合规检查和 BOM 预算功能。

零、需求补全规则

- 本项目最接近 `manufacturing-scada-small` 场景模板，请把模板仅作为需求发现工具，不要把模板默认值当成项目事实。
- 先检查下面已经给出的条件，不要重复询问已知信息。
- 如果仍缺少会明显改变架构、容量或候选技术资格的 Mandatory 信息，最多先提出 3–7 个最高优先级问题。
- 对不影响当前阶段判断的次要缺口，可以使用明确标注的 assumption/TBD 继续分析。
- 场景模板不得自动加入 HCI、HA、双核心、防火墙、信创或特定厂商。

一、项目背景

- 工厂为两层建筑，一期使用面积约 5,000 平方米，后续可能扩展到 10,000–15,000 平方米。
- 一期建设 SCADA 集中监控、历史数据、报警、报表、BI 大屏和少量现场操作站。
- 不预设 HCI、双机、双核心或防火墙，是否需要由需求和风险决定。
- 优先采用维护简单、生命周期稳定、当前可采购的设备。
- 如果没有明确国产化/信创要求，不要强制加入信创约束。

二、SCADA / OT 规模

- SCADA 授权规模约 3,000 I/O 点。
- 历史记录点约 1,200 点。
- 平均有效采样周期按 5 秒估算，关键点可更快。
- 历史数据至少保留 1 年，并预留 30% 容量余量。
- 4 个现场操作站。
- 2 块 100 英寸大屏，用于生产、报警、设备状态和能耗展示。
- 大屏必须具备浏览器/BI 展示能力；若显示设备本身不具备，应把 OPS 或等效播放设备计入完整 BOM 和价格范围。
- 需要 OPC UA、主流 PLC 通讯驱动、报警、历史趋势、报表/API。
- 有少量设备需要通过 SCADA 发起远程启停，但 PLC/设备侧安全联锁必须保持最高优先级；需要权限、二次确认、操作审计、命令反馈和拒绝原因。

三、服务器与存储

计划用 1 台物理服务器集中承载 SCADA、Historian、数据库、Web/BI 和接口服务，请先判断单服务器架构是否合理，再做容量计算。

初始参考配置：

- 2U 机架式服务器
- 单 CPU 12–16 核
- 128GB ECC
- 2×960GB 企业级 SSD RAID1：系统
- 2×1.92TB 企业级 SSD RAID1：数据库/热数据
- 4×4TB 企业级 HDD RAID10：历史归档
- 硬 RAID，带缓存和掉电保护
- 独立 BMC
- 双电源 1+1
- 至少 2×1GbE
- 3 年质保

请根据实际负载重新计算 CPU、内存、Historian、数据库和存储容量，不要因为我给了参考配置就默认它一定正确。

四、网络

- 一期预计约 30 个有线 IT/OT 端口。
- 规划 5 个 VLAN：管理、服务器、SCADA/操作站、生产 OT、访客/办公。
- 部分 VLAN 需要互通，请明确 Layer-3 路由功能由谁承担。
- 优先判断 1 台 48 口轻三层网管交换机是否足够，不要因为有多个 VLAN 就自动增加核心交换机。
- 后续端口数可能增长约 50%。
- 如果安全边界确实需要防火墙，请说明触发条件、保护对象和性能口径；否则不要为了“完整”而强行加入。

五、UPS

UPS 只保护服务器、交换机和必要管理设备，不保护现场电脑和大屏。

目标：

- 断电后至少支撑 10 分钟或完成数据库/SCADA 安全停止与服务器优雅关机。
- 必须同时校验 W、VA、容量余量、目标负载下运行时间曲线、波形/服务器电源兼容性，以及 USB/串口/网络关机接口和软件兼容性。
- 任何更便宜的 UPS SKU 必须先通过 technical-fit gate，只有 `eligible-for-pricing` 才能作为下调预算依据。

六、已有预算基线

这是一个“重新核价”任务。下面是现有单价基线，不能被弱证据静默覆盖：

- 中心服务器：92,000 元/台
- 48 口交换机：6,500 元/台
- UPS：5,000 元/台
- 现场控制电脑：4,500 元/套，共 4 套
- 100 英寸大屏：22,000 元/块，共 2 块
- 国产 SCADA 软件包：60,000 元/套

对于服务器、存储、配置型防火墙等 `configurable-enterprise` 设备，如果要下调已有预算，必须执行预算 revision guard。

PConline/ZOL 同系列部分配置、裸机价、起售价、历史成交、组件估算、工程估算只能作为背景，不能单独把已有预算往下调。

如果项目目录或用户提供资料中存在厂家客服、官方店、授权代理的当前人工报价，应优先复用；只要渠道、日期、配置匹配和商业范围可确认，即使没有公开 URL，也可以作为强证据。

七、设备选型与实时价格

请基于当前可获得信息：

1. 查找仍在售/可采购的候选产品；
2. 技术规格优先使用厂商官网、Datasheet、配置指南、兼容性矩阵或生命周期资料；
3. 价格按 `configurable-enterprise`、`fixed-sku`、`commodity-component` 分类选择证据渠道；
4. 对企业定制设备优先寻找完整配置级当前报价；
5. 对固定 SKU 收集多个当前可比报价；
6. 标出税、维保、License、附件、实施、运输等商业范围是否完整；
7. 对不能作为主预算锚点的低价信号保留“排除原因”；
8. 不要为了匹配低价 SKU 反向降低原技术需求。

八、Mandatory 约束与厂商比较

对关键设备至少给出 2–3 个候选厂商/型号或产品系列，并执行 vendor comparison。

先把项目 Mandatory 技术要求结构化为约束，再做评分：

```text
候选属性
→ Mandatory PASS / CONDITIONAL / FAIL
→ PASS 方案进入偏好排序
```

规则：

- 不满足 Mandatory 的候选必须 FAIL 并淘汰，不能靠评分救回来；
- 缺少 Mandatory 证据的候选标记 CONDITIONAL，不能因为分数高就排在 PASS 前面；
- 只有 PASS 候选进入最终推荐排名。

偏好评分维度至少包括：

- 生命周期/当前可采购性
- 配置匹配度
- 维保与实施
- 扩展性
- 运维复杂度
- 当前价格证据质量
- 3/5 年 TCO（有足够数据时）

九、TCO 分析

对最终满足 Mandatory 的主要候选计算 3 年和 5 年 TCO。

若数据可获得，至少纳入：

- 当前采购 CAPEX
- 一次性实施
- 平均 IT 输入功耗（不是双电源铭牌功率之和）
- PUE
- 当前当地电价
- 年度维保
- 年度 License/subscription
- 明确存在且未被 PUE 重复覆盖的设施/机架/其他 OPEX

要求：

- 采购价和 TCO 分开呈现；
- 不要为了算 TCO 而虚构未知功耗、电价、PUE 或维保费用；未知项标记 TBD/Estimated；
- TCO 只用于比较技术合格方案，不能覆盖 Mandatory、安全、合规或兼容性要求；
- 如果 TCO 输入不足以形成可靠结论，给出公式和待确认项，不制造假精度。

十、招标/RFQ 参数

基于推荐方案生成一版厂商中立的采购/询价技术参数：

- 按 Mandatory / Recommended / Optional 分类；
- 关键参数要可测量、可验收；
- 对服务器、交换机、UPS、大屏、现场电脑和 SCADA 软件分别生成；
- 不要把推荐品牌型号直接写成排他性参数；
- 无法确认的参数写 TBD，不要虚构。

十一、网络拓扑

生成：

1. Mermaid 逻辑网络拓扑；
2. Graphviz DOT 拓扑。

拓扑必须与最终 BOM 和架构决策一致。

不要虚构 VLAN ID、IP 地址、具体物理端口、冗余链路或安全区域；未知项使用逻辑名称/TBD。

十二、合规与风险检查

检查至少包括：

- 是否存在单点故障；
- 单服务器方案的 RAID、UPS、自动关机和独立备份措施；
- Layer-3 路由归属；
- OT/IT 访问边界；
- SCADA 远程启停的权限、联锁、二次确认、审计和反馈；
- 历史数据容量与保留周期；
- License/客户端/Web/OPC UA/驱动是否漏项；
- UPS 是否真实满足负载和续航；
- 大屏是否真实具备 Web/BI 播放能力；
- Mandatory 条件是否全部有证据；
- 税、维保、实施、运输是否已经确认。

十三、最终输出

请按以下顺序输出：

1. 已知条件 / 假设 / TBD
2. 场景模板匹配结果与尚需补充的高优先级问题（如有）
3. 架构决策与理由
4. CPU / 内存 / Historian / 存储 / 网络端口 / UPS 容量计算
5. 推荐技术规格与 Mandatory 条件
6. 当前候选设备的 PASS / CONDITIONAL / FAIL 约束结果
7. PASS 候选的厂商比较与推荐排序
8. 3/5 年 TCO（数据充分时）
9. 当前价格证据表：报价、日期、渠道、配置匹配、证据等级、排除原因
10. 已有预算 revision 结果：旧价格、新价格/区间、是否允许修改、guard decision
11. 推荐 BOM 和预算区间
12. 10% 不可预见费及总预算
13. 可压缩项 / 可选项 / 升级触发条件
14. 招标/RFQ 技术参数
15. Mermaid 网络拓扑
16. Graphviz DOT 网络拓扑
17. 合规检查与风险清单
18. 待厂家/用户确认事项

输出预算时不要在税、维保、实施或运输尚未确认的情况下笼统写“全部含税到货”。请明确哪些项目已确认，哪些仍为 `Needs confirmation`。
```
