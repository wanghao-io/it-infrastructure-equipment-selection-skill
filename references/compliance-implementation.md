# Compliance Implementation Matrix

Use when evaluating existing equipment or planning remediation against a specified standard/tender.
Verify the applicable standard edition, clause and project scope from authoritative evidence at execution time.
Do not infer compliance from appliance count or claim certification without the authorized assessment.

Use `assets/compliance-implementation-template.csv`. Keep these axes separate:

- requirement source/edition and applicability;
- standard requirement, assessment practice, or engineering recommendation;
- design coverage;
- existing device capability: possible / conditional / impossible / unknown;
- implementation state: unconfigured / configured / unknown;
- verification state: untested / tested-pass / tested-fail / not-applicable;
- gap category: configuration / license / hardware / organization / physical-environment / evidence;
- owner, implementation action, acceptance evidence, linked design section and BOM effect.

Missing policy/fire/physical-site documentation is missing evidence, not automatically a measured field failure.
An existing feature can avoid a new appliance only after capacity, license, retention, integration and support fit.
A capability checkbox does not mean it was configured, exercised or assessed.
Do not buy network appliances to compensate for an organizational procedure gap.

For every remediation, update the corresponding design/RFQ/acceptance item and cost implication.
Keep unknowns and conditional capabilities visible. Use the matrix to assign work, not to calculate an unsupported overall compliance percentage.
